Stack Detection — Preview Capabilities V2

Spec: docs/specs/2026-05-16-preview-capabilities-v2-design.md · Status: Approved

The single cssSystem detection field is replaced by 6 independent dimensions, each with its own support level. The readonly screen now shows the actual detected stack for the project instead of a static compatibility table.

Root causes fixed
  • → HyperIDE itself was detected as shadcn because class-variance-authority was used as a trigger — CVA is a utility, not a shadcn signal
  • → HyperIDE shown in readonly mode despite using fully supported tech (Tailwind + bun bundler); bun was in PreviewModeManager but absent from FULL_EDIT_BUNDLERS
  • → bun.lockb was treated as a bundler signal — it is a package manager lock file only
  • → Auto-start showed the "Start Dev Server" button instead of a spinner while the server was starting

New ProjectCapabilities shape
// Detected stack
cssFramework:   CssFramework;     // tailwind | cssmodules | emotion | …
designSystem:   DesignSystem;     // shadcn | tamagui | mui | none | …
jsFramework:    JsFramework;      // react-vanilla | react-nextjs | preact | …
router:         RouterType;       // nextjs-app | remix | tanstack-router | …
bundler:        Bundler;          // vite | webpack | rspack | bun | parcel | …
packageManager: PackageManager;   // bun | npm | pnpm | yarn | yarn2

// Derived — no more redundant support* fields
canRender:      boolean;  // jsSupport !== 'unsupported' && bundlerSupport !== 'unsupported'
canWriteStyles: boolean;  // CSS_SUPPORT[cssFramework] === 'full' && BUNDLER_SUPPORT[bundler] === 'full'
readonly:       boolean;  // canRender && !canWriteStyles
Support maps (CSS_SUPPORT, DS_SUPPORT, JS_SUPPORT, BUNDLER_SUPPORT) exported from types.ts — usable by both extension host and webview. Also: uiKit → designSystem rename across AIBridge, StateHub, styling-tools.
