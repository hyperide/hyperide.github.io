What we delivered

Extension 0.1.75 is published

We cut 0.1.75, tagged it ext-v0.1.75 and published it to Open VSX and the VS Code Marketplace on 16 October. The publish run validated the version, built the VSIX and confirmed that both registries list the tag. The release carries the changes the team had merged since 0.1.74; the release cut and its publication are ours.

Technical detail
  • Version and lockfile set to 0.1.75 with a 24-line [0.1.75] changelog entry dated 15 October.
  • The Publish VS Code Extension run started 16 October 01:23 UTC on the tag, and every step succeeded, including "Verify both registries have the tagged version".
  • The pull request’s own CI run passed lint, types, tests and the extension production build on its final commit.

Key pull requests: #825

Git push isolates credentials and preserves transport settings

Push credentials now come only from the checked project, the project’s TLS and transport settings are kept, and Git configuration inherited from the environment is refused. Credential helpers are reset for each operation and temporary credentials are removed afterwards. Failures come back as a clear authentication or pull-needed response instead of raw Git output.

Technical detail
  • Push authority comes from checkedProject; both push paths run without interactive prompts (server/utils/git-credentials.ts, server/services/git.ts).
  • Typed failures keep the 401 needsAuth and 409 needsPull responses without exposing raw diagnostics (server/services/git-push-error.ts).
  • Tests include git-push-tls.test.ts, git-credential-policy.test.ts, git-credentials-security.test.ts and git-push.security.test.ts. Two cases: a file-transport restriction that a credentialed push does not weaken, and a trusted Perl pre-push hook that does not load credential-capturing code through inherited configuration.
  • At the recorded 14 October revision the pull request lists 137 focused Git, Hono and CI tests passing, and 7,831 application tests passing on the parent commit.

Key pull requests: #810

Dependency audits and MCP request limits

The pull request records the extension’s high-severity npm audit and the root application’s high-severity bun audit both passing. The extension’s MCP endpoint now rejects request bodies over 4 MiB with a 413 before it builds a server, because the SDK’s own limits do not apply to bodies the extension parses itself.

Technical detail
  • Extension: @modelcontextprotocol/sdk moved to 1.32 and the markdown-it advisory was cleared with a non-force npm audit fix; the @hono/node-server override stays within its major version (#837).
  • Root: zod, happy-dom, dompurify and undici were updated for advisories in the MCP SDK, DOMPurify, happy-dom, undici, zod and body-parser (#837).
  • HyperMcpServer.ts counts streamed bodies as well as declared lengths. MAX_MCP_BODY_BYTES is 4 MiB and maxToolInputElements is 50,000. New tests send a 4 MiB padded body, a 16 MiB declared body and eight 1 MiB chunks.
  • #810 added a Security Scan workflow with a dependency audit and Semgrep; it passed on the 14 October revision, where the pull request records Semgrep running 177 rules over 2,820 targets with no findings.

Key pull requests: #837 · #810

Local pre-commit checks run on a stock Ubuntu shell

The staged-content conflict-marker check now works under dash, the default shell on Ubuntu. All eight Lefthook jobs passed on native Ubuntu in 15.41 seconds, so the checks that guard each commit run there.

Technical detail
  • Fixes are in ci/local-checks.sh and lefthook.yml, covered by scripts/__tests__/conflict-markers.test.ts and ci/local-checks.test.cjs.
