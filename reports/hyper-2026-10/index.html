Merged to main · 18 to 20 August 2026

The inspector knows whether a component forwards className or style before an edit

Before. The inspector's read facts hard-coded acceptsClassName and acceptsStyle to true. The planner could pick a channel on a custom component that silently drops the prop. A color click then changed nothing and showed no error. The SaaS browser path never called a detector at all.

Now. A per-channel forward detector (§9.2a, “A1”) now feeds the VS Code and SaaS read paths and the extension's pre-write gate. It traces the component's render body, tells the root element from a descendant, and recognizes asChild/Slot and styled-components wrappers, including one level of styled(Component). A channel counts as not forwarding only on a high-confidence negative.

Merged to main · 18 August 2026

A style edit on a component that cannot take the prop is refused and rolled back

Before. A padding, margin, radius or width edit on a component that did not forward style wrote a dead prop onto it. The DOM stayed the same, nothing rolled back, no warning appeared, and TypeScript reported an error. Two shapes caused it: a component that forwarded className but not style, and one imported from a monorepo workspace package that resolved as external.

Now. The shared executor checks every channel a write will touch before it mutates anything and returns a structured nonForwarding refusal. The extension turns that into its verify-and-retry or warn-and-roll-back path, and the SaaS route avoids the dead prop and the TypeScript error and returns the warning. The extension also serializes writes per file, tags each write with a scoped marker so verification targets the right element, takes the undo snapshot inside the lock, and shows a native warning with Details and an AI-fix action.

Merged to main · 21 August 2026 · partial against the spec target

A color edit that cannot find its CSS rule now lands as an inline style

Before. When the CSS Module or plain CSS rule for an edit could not be located, the executor hard-failed. The color edit did nothing visible and no usable error appeared. The spec called this a dead click.

Now. On a rule miss the executor writes the declarations onto the source element's own style attribute. It finds the JSX file through the element reference, because the owner's path is the CSS file. It acts only on a plain .class or #id target in the base condition, re-runs the dead-prop forwarding check first, and reports a distinguishable failure if every declaration drops. Conditional, at-rule and combinator targets still fail.

Merged to main · 19 to 20 August 2026

A second Fill-color pick replaces the color instead of leaving a stale class

Before. After an earlier fix left an inline-style override on an element, every later edit of the same property went through the inline branch. The same-group Tailwind class, such as bg-*, in a cn() plus string-concatenation className stayed stale. A className bound to a same-file constant also stayed stale, and the sync failure was swallowed.

Now. The write now replaces the existing same-group class and never appends one, and only for single-property writes. A same-file constant is followed when the live DOM shows a conflict. If the class sync throws, the write result carries a classSyncWarning and the authoritative inline write is not blocked.

A Canvas drag-move is proven by the preview, and rolled back when wrong

Before. The runtime had no drop verification. A successful API reply, a changed file or a non-empty diff could be reported as success, and a failed move stayed on disk behind an optional Undo button. Now. A drag writes temporary data-hc-moveid markers at positions taken from the syntax tree, without reprinting the file or adding a wrapper. The preview reads the committed fibers carrying the markers. The move counts as verified only with exactly one carrier per marker, unchanged content, the requested order in fibers, DOM and layout, no portal, and the outline on the moved element. One owned compare-and-swap write then commits the unmarked image. On failure the markers are restored, the restore echo is awaited and the move is rolled back. An order drop edits only the order-* token across every affected file in one undo batch.
